# 404 Page Design

## Goal

Give visitors a clear, on-brand recovery path when a requested route does not exist or a page is planned but is not available yet.

## Design

Add a Next.js App Router `app/not-found.tsx` page inside the existing root layout. The shared navbar and footer remain visible so the page feels like part of the portal and preserves normal navigation and account controls.

The main content is a compact, centered state on the warm-neutral canvas:

- A small `404` label establishes the error state.
- The heading says `This page isn’t available yet.`
- Supporting text explicitly covers both cases: the requested page may not exist, or it may be coming soon but is not available yet.
- The primary `Browse apps` button links to `/#apps`.
- A secondary `Back home` link returns to `/`.

Use the existing `portal-heading`, `portal-button`, `portal-button-primary`, and `portal-button-secondary` styles. Keep the composition responsive, keyboard accessible, and free of new dependencies or decorative assets.

## Behavior and accessibility

`app/not-found.tsx` provides the framework-native 404 response for unknown App Router paths. The page uses semantic `main`, heading, paragraph, and links. Both actions have visible focus states through the existing global focus rule and retain at least the existing control target height on small screens.

## Verification

Run ESLint and a production build. Confirm that an unknown route renders the shared shell plus the 404 content, that `/#apps` reaches the apps section, and that both actions remain usable at narrow widths and with keyboard focus.
